# Feature parity assessment

This is the historical gap assessment before the full-parity implementation. The applicable operations gaps below are implemented on `codex/full-feature-parity`; see [current implementation status](../IMPLEMENTATION.md) and [operations guide](../operations.md). The live-game acceptance boundary still applies.

Checked October 25, 2026 against S2Script CS2 Egg main at [`8857a551`](https://github.com/s2script/s2script-cs2-egg/tree/8857a5519ac4cb56b26716f6d57f7956f60d3a8e). Source comparison covers the implementation through `18918bb`, subsequently merged into main as `66923fa`.

Assessment: the requested installation, game-sharing and framework-cache foundation is implemented. Source Egg does **not** yet have the reference node's full operations suite. A percentage would hide large differences between core delivery and production validation.

## Missing reference operations

- Scheduled private-data backups, listing and stopped-server restore: [reference backup](https://github.com/s2script/s2script-cs2-egg/blob/8857a5519ac4cb56b26716f6d57f7956f60d3a8e/docs/modules/backups.md).
- Node/server CPU, memory, network metrics, terminal `top` and Prometheus exporter: [reference metrics](https://github.com/s2script/s2script-cs2-egg/blob/8857a5519ac4cb56b26716f6d57f7956f60d3a8e/docs/modules/metrics.md). Existing A2S/player/build status is not resource-metrics parity.
- Scheduled server demo/log/dump cleanup and cache/archive retention: [reference cleanup](https://github.com/s2script/s2script-cs2-egg/blob/8857a5519ac4cb56b26716f6d57f7956f60d3a8e/docs/modules/cleanup.md). Source has protected generation pruning, not this wider cleanup service.
- Optional host Docker/build-cache/journal maintenance, disk/reboot notices and unattended-upgrade setup: [reference maintenance](https://github.com/s2script/s2script-cs2-egg/blob/8857a5519ac4cb56b26716f6d57f7956f60d3a8e/docs/modules/maintenance.md).
- Node self-update and uninstall commands: [reference node lifecycle](https://github.com/s2script/s2script-cs2-egg/blob/8857a5519ac4cb56b26716f6d57f7956f60d3a8e/docs/node.md#updates-and-removal). Source binary upgrades currently rerun the verified bootstrap; `sourcenode update GAME` updates a game.

## Scope and validation boundaries

Workshop/custom-map caching and the CS2 connection guard were intentionally excluded. Canary promotion, automatic health rollback and proactive framework-only restart scheduling remain Source proposal targets; the reviewed reference VPK implementation does not establish these as delivered reference features. Framework checks at startup are common to both projects.

The alpha release [`v0.0.1-alpha.1`](https://github.com/edgegamers/source-egg/releases/tag/v0.0.1-alpha.1) is published and its [release workflow succeeded](https://github.com/edgegamers/source-egg/actions/runs/40194609784). This is a prerelease: use the beta channel; the default stable bootstrap needs a non-prerelease release. Source main [CI passed](https://github.com/edgegamers/source-egg/actions/runs/40194608991), including build/startup fixtures. Neither publication nor CI proves five real game installs, successful client authentication/joins, framework loading, map transitions or mixed-game rollout behavior on Wings. Those remain the principal acceptance gate, especially current standalone CS:GO. The older no-release/feature-branch statements in `docs/IMPLEMENTATION.md` are stale at this snapshot.
