# Per-server plugin manager

Approved design: server owners manage arbitrary third-party plugin packages without node access. Public GitHub and private GitLab release assets are selected by exact name or glob, with explicit per-package file/subtree mappings into the game directory. ZIP, tar.gz and loose files are supported. No package scripts execute. GitLab release links can point at job artifacts; source compilation and dependency solving are outside this package updater.

The editable `.source/plugins.json` is the source of truth, with `egg plugins` panel console shortcuts. Per-server credentials live separately in `.source/plugin-credentials.json`, never a shared node cache. Anyone with panel console/files permission can manage plugins; same-UID game plugins can read server files. No claim of isolation from installed plugin code.

Check at startup and every six hours (configurable). Stable releases by default, optional prereleases and exact tags. Print visible startup notices naming installed and available versions. Failed checks leave installed plugins usable. Stage downloads without installing; approval binds an immutable package ID and recipe. Apply approved changes before the next game process starts, never hot reload or force restart. Both standalone and node-managed flows use the same private server storage.

Mappings preview selected paths. Reject ambiguous assets, missing mapping sources, duplicate targets, changed managed path sets, traversal, symlinks/special archive entries and limits violations. Changed package layouts require explicit preview and acceptance of the new exact package. Complete packages may include plugins, extensions, translations, gamedata and default configuration. Existing configuration/data/logs are seed-only; custom preserve paths extend this policy. Collision checks include framework receipts and other plugins. Existing unowned code needs explicit adoption, never automatic overwrite. Modified managed files block updates until an explicit keep/replace decision.

Before changing files create a durable rollback journal. Recover interrupted transactions at startup, restore failed installations, retain two previous installed snapshots for queued rollback. Preserve configuration/data through update, rollback and uninstall. Removing a manifest entry stops tracking but does not delete files. Explicit uninstall previews eligible managed files and removes only unchanged owned files at restart.
